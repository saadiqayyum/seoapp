# SEO Audit Dashboard — Next.js Implementation Plan

## Context

We have a Python LangGraph SEO agent (`C:\dg-seo-agent`) that audits a domain against keywords, producing:
- `report_data.json` — structured data with rankings, competitors, issues, page speed, etc.
- `seo_report.md` — narrative markdown report generated by LLM

This Next.js App Router project creates a dashboard to visualize those reports with a modern, clean SaaS UI inspired by byword.ai.

---

## Tech Stack

| Layer | Choice |
|---|---|
| Framework | Next.js 15 (App Router, TypeScript, `src/` directory) |
| Styling | Tailwind CSS + `@tailwindcss/typography` |
| UI Components | shadcn/ui |
| Charts | Recharts (via shadcn `chart` component) |
| Dark/Light Mode | `next-themes` |
| Markdown Rendering | `react-markdown` + `remark-gfm` |
| Icons | `lucide-react` (ships with shadcn) |
| Package Manager | **yarn** |

## Routes

| Route | Purpose |
|---|---|
| `/` | Overview dashboard — summary cards, rank distribution, health score, keyword table |
| `/keywords` | Keyword list with sortable table |

## Data Flow

1. **Server Components by default** — all `page.tsx` files are Server Components
2. `lib/data.ts` exports `getReportData()` which reads `public/sample-data/report_data.json` via `fs` (server-only)
3. Pages call `getReportData()` at the top level and pass data as props to child components
4. Interactive components (charts, tabs, accordions) are `"use client"` and receive data via props
5. No global state management — data is static per report load
6. **Future:** swap `fs.readFileSync` in `data.ts` for API `fetch()` — no component changes needed

## TypeScript Interfaces (lib/types.ts)

```typescript
export interface ReportData {
  domain: string;
  generated_at: string;
  keywords: KeywordData[];
}

export interface KeywordData {
  keyword: string;
  your_rank: number | null;
  your_url: string | null;
  your_page: number | null;
  serp_features: SerpFeatures;
  top_competitors: Competitor[];
  on_page_issues: string[];
  missing_topics: string[];
  backlink_gap: string[];
  internal_link_score: number;
  internal_link_issues: string[];
  page_speed: PageSpeed | null;
  raw_competitor_data: RawCompetitorData[];
}

export interface SerpFeatures {
  has_featured_snippet: boolean;
  has_knowledge_panel: boolean;
  has_video_carousel: boolean;
  has_image_pack: boolean;
  has_local_pack: boolean;
  people_also_ask: string[];
}

export interface Competitor {
  rank: number;
  url: string;
  title: string;
  domain: string;
}

export interface PageSpeed {
  score: number;
  lcp: number; lcp_rating: WebVitalRating;
  fcp: number; fcp_rating: WebVitalRating;
  cls: number; cls_rating: WebVitalRating;
  inp: number; inp_rating: WebVitalRating;
  ttfb: number; ttfb_rating: WebVitalRating;
}

export type WebVitalRating = "FAST" | "AVERAGE" | "SLOW";

export interface RawCompetitorData {
  url: string;
  title: string;
  meta_description: string;
  h1: string[];
  h2: string[];
  h3: string[];
  word_count: number;
  has_schema: boolean;
  internal_links: number;
  external_links: number;
}

export interface ActionItem {
  keyword: string;
  category: "on-page" | "content" | "backlinks" | "internal-links" | "speed" | "serp";
  priority: "high" | "medium" | "low";
  title: string;
  description: string;
}
```

## Implementation Phases

### Phase 1: Scaffolding
1. `npx create-next-app@latest . --typescript --tailwind --eslint --app --src-dir --import-alias "@/*" --use-yarn`
2. Init shadcn: `yarn dlx shadcn@latest init`
3. Install shadcn components (card, button, badge, table, sidebar, tabs, progress, accordion, chart, etc.)
4. `yarn add next-themes react-markdown remark-gfm @tailwindcss/typography`
5. Create `lib/types.ts` — all TypeScript interfaces
6. Create `lib/data.ts` — mock data loader
7. Create `public/sample-data/report_data.json` — realistic mock data
8. Build root layout with sidebar navigation + theme toggle

### Phase 2: Overview Page
1. Summary cards component (4 metric cards)
2. Health score radial gauge
3. Rank distribution bar chart
4. Keywords quick-glance table
5. SERP features summary
6. Compose into `app/page.tsx`

### Phase 3: Keyword Detail
1. Keywords list page (`/keywords`)
2. Dynamic `[keyword]` page with tabbed layout
3. All keyword-detail sub-components:
   - Rank badge, SERP feature icons
   - Competitor table, on-page issues
   - Content gaps, backlink opportunities
   - Internal link gauge, CWV gauges
   - People Also Ask accordion

### Phase 4: Competitors & Actions
1. `lib/computations.ts` — aggregation and prioritization functions
2. Competitors analysis page
3. Action items page with category filters

### Phase 5: Report & Polish
1. Markdown renderer with `@tailwindcss/typography` prose styling
2. Loading skeletons for all pages
3. Responsive design pass (mobile sidebar collapse, card stacking)
4. Dark/light mode QA across all pages
